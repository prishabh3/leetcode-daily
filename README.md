# LC-Sync — Personal DSA Learning & GitHub Automation

[![Tests](https://img.shields.io/badge/tests-74%20passed-brightgreen.svg)]()
[![TypeScript](https://img.shields.io/badge/TypeScript-5.8-blue.svg)]()

**LC-Sync** is a privacy-conscious, local-first Chrome extension that automatically synchronizes accepted LeetCode solutions to your personal GitHub repository, backfills complete historical submissions, structures an 8-section learning journal, and schedules offline spaced-repetition revisions.

---

## Key Features

- **Reliable Submission Sync**: In-page DOM observer detects terminal verdicts (`Accepted`), snapshots submitted source code from Monaco/CodeMirror, and synchronizes to GitHub in the background without interruptions.
- **Historical Submissions Import**: Backfills complete past submissions across pagination into your solutions repository with atomic batch commits, preview analytics, commit date strategy selection, and checkpoint resumability.
- **Three Import Modes**:
  - *Mode A (Default)*: All historical accepted versions (`solutions/.../history/<id>/solution.ext`).
  - *Mode B*: Latest accepted submission per problem and language for a compact repository.
  - *Mode C*: All submission attempts including unsuccessful attempts, kept isolated under `solutions/.../attempts/<id>/`.
- **Atomic Multi-File Commits**: Uses the GitHub Git Database API (`blobs` → `trees` → `commits` → `refs`) to update solution code, `metadata.json`, `notes.md`, `sync-index.json`, `README.md`, and `assets/progress.svg` in a single Git commit.
- **UTF-8 Safe Encoding**: Lossless Base64/UTF-8 conversion prevents character corruption, broken emojis, and mojibake in generated Markdown and Git commits.
- **Deduplication & Concurrency Retries**: Primary submission ID and secondary normalized SHA-256 content hashing prevent duplicate commits. Automatic exponential backoff resolves Git branch conflicts (HTTP 409).
- **Spaced Repetition Engine**: Calculates revision dates based on recall confidence (1–5) and lapses ($1 \rightarrow 3 \rightarrow 7 \rightarrow 14 \rightarrow 30$ days), surfacing an urgent Daily Review Queue.
- **Structured Learning Journal**: Pre-populates 8-section learning notes (Intuition, Key Observation, Approach, Correctness, Complexity, Edge Cases, Mistakes, and Simplified Explanation).
- **Two Separate Repositories**: Keeps this software repository distinct from your personal solution repository.

## Quick Start

### 1. Build from Source

```bash
# Clone the repository
git clone https://github.com/your-username/lc-sync.git
cd lc-sync

# Install dependencies
npm install

# Run the test suite (74 automated tests)
npm test

# Verify TypeScript type safety
npm run typecheck

# Build the production Chrome extension
npm run build
```

### 2. Load into Google Chrome

1. Navigate to `chrome://extensions/` in Chrome.
2. Enable **Developer mode** (toggle in the top-right corner).
3. Click **Load unpacked** (top-left).
4. Select the `dist/` directory generated by `npm run build`:
   `/path/to/LC-Daily/dist`
5. Pin the **LC-Sync** extension icon to your toolbar.
6. Open **Options** to configure your GitHub Personal Access Token and target repository (`owner/repo`).

> For full token configuration and troubleshooting, see [`docs/SETUP.md`](./docs/SETUP.md).

## How It Works

```
LeetCode → DOM Observer → Verdict State Machine → Queue & Deduplication → GitHub Git DB API → Solutions Repository
```

1. **Detection**: The content script monitors LeetCode problem pages (`leetcode.com/problems/*`). Clicking **Submit** snapshots the active editor code and begins evaluating the terminal verdict.
2. **Filtering**: Non-accepted verdicts (`Wrong Answer`, `Time Limit Exceeded`, `Runtime Error`, `Compile Error`) are ignored during normal live sync.
3. **Background Sync**: On `Accepted`, the service worker verifies GitHub credentials and commits the code, metadata, notes, and progress index.
4. **Non-Blocking Feedback**: An in-page pill transitions from `Evaluating...` to `✓ Synced: [Title] → GitHub [View Commit]`. Zero interrupting popups or copy-paste required.

For deep architectural diagrams and state machines, see [`docs/ARCHITECTURE.md`](./docs/ARCHITECTURE.md).

## Historical Submission Import

To import your previous LeetCode submissions:

1. Click the LC-Sync extension icon and select **Open Dashboard & Journal** (or right-click → Options).
2. Click **📥 Import Historical Submissions**.
3. **Connection Check**: The wizard verifies that your LeetCode browser session and GitHub repository are active.
4. **Configure**: Select your preferred import mode (**Mode A**, **Mode B**, or **Mode C**), **Commit Date Strategy** (Option A: Commit on Import Date vs. Option B: Use Original Submission Date), optional date range, and language filters.
5. **Preview**: Inspect the discovered history, distinct problems, already synced solutions, timestamp integrity, and new records to be imported.
6. **Execute**: The importer processes submissions in bounded atomic batches (5–10 per commit) with live progress and automatic checkpointing.
7. **Resumable**: If cancelled or interrupted, your progress is saved, allowing you to resume anytime without re-importing duplicate records.

## Security & Privacy

- **Local-First**: LC-Sync has no proprietary backend servers, telemetry, or third-party proxy endpoints. Network calls occur directly between your browser, LeetCode, and `api.github.com`.
- **Zero External AI Transmission**: Your code, notes, and solutions remain entirely local and are never transmitted to external AI APIs.
- **Credential Isolation**: GitHub Personal Access Tokens are stored solely in `chrome.storage.local` (never in `chrome.storage.sync` or cloud profiles).
- **Secret Redaction**: Errors and diagnostic messages sanitize tokens matching `ghp_...` and `github_pat_...`.
- **No Password Access**: LC-Sync never asks for or stores LeetCode passwords.

For our complete security model, see [`docs/SECURITY.md`](./docs/SECURITY.md).

## Third-Party Compatibility & Limitations

- **Website Changes**: LeetCode periodically alters its DOM structure and class names. LC-Sync uses multi-selector fallbacks (Monaco lines, CodeMirror, standard pre/code) and a manual import dialog for full resilience.
- **Rate Limits**: Historical imports utilize conservative request intervals and exponential backoff to respect GitHub (5,000 req/hr) and LeetCode rate limits.
